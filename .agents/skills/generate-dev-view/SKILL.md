# generate-dev-view

This skill acts as the final step in the "Translation Layer" (Stage 2) of Spec-Driven Development (SDD). It creates the "Architecture Blueprint" drawing heavily from Domain-Driven Design (DDD) principles to ensure the business intent maps cleanly to the physical codebase.

## Usage

Use this skill only after the `generate-ba-view` and `generate-qa-view` skills have completed.

### Parameters (JSON Schema)

```json
{
  "type": "object",
  "properties": {
    "refined_intent_json": {
      "type": "string",
      "description": "The exact JSON output generated by the refine-intent skill."
    },
    "ba_view_markdown": {
      "type": "string",
      "description": "The markdown output generated by the generate-ba-view skill."
    },
    "qa_view_markdown": {
      "type": "string",
      "description": "The markdown output generated by the generate-qa-view skill."
    },
    "repo_spec_path": {
      "type": "string",
      "description": "Optional. The path to the global repository guidelines (e.g., 'AGENTS.md'). Defaults to 'AGENTS.md' in the workspace root."
    }
  },
  "required": ["refined_intent_json", "ba_view_markdown", "qa_view_markdown"]
}
```

## Execution Instructions (For the LLM Agent)

When this tool is invoked, you MUST strictly adhere to the following rules:

1. **Strict Dependency Chain:** You MUST NOT invent or alter business logic. You are strictly bounded by the `ba_view_markdown` and `qa_view_markdown`.
2. **Read the Grounding Rules:** You MUST read the `AGENTS.md` file located at `repo_spec_path`. Your technical decisions MUST NOT violate the established repository architecture or dependencies.
3. **No Implementation Details:** Do NOT write the actual source code (no Javascript, Python, Java, etc. implementations). Code rots quickly in specs. Provide ONLY structural boundaries: file names, API contracts (OpenAPI), schema deltas, and architecture patterns.

### The Output Format

You MUST generate the output exactly as follows:

```markdown
### 1. File Manifest
* `[NEW]` file:///path/to/new_file
* `[MODIFY]` file:///path/to/existing_file
* `[DELETE]` file:///path/to/deprecated_file

### 2. API Contracts
[Insert OpenAPI/Swagger snippets or GraphQL schema definitions for any modified boundaries. If none, state "No API changes required."]

### 3. Schema Deltas
[Insert Database migration concepts or Entity modifications. If none, state "No DB changes required."]

### 4. Architectural Notes
[Provide any critical notes on how the DDD bounded contexts map to this feature, or any specific dependency updates required to satisfy the NFRs from the BA View.]
```

### Action After Generation

Once generated, present the final output to the user. The Translation Layer is now complete. The combined outputs of these three skills form the final `Delta Spec` for the feature, which can now be passed to the Stage 3 Execution Layer.
