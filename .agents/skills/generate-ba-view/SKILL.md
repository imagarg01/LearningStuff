# generate-ba-view

This skill acts as the first step in the "Translation Layer" (Stage 2) of Spec-Driven Development (SDD). It strictly limits itself to logic, flow, and user experience, stripping away any technical jargon so Business Analysts and Product Owners can rapidly verify intent.

## Usage

Use this skill immediately after the `Refined_Intent` has been generated by the `refine-intent` skill (and approved by the PO).

### Parameters (JSON Schema)

```json
{
  "type": "object",
  "properties": {
    "refined_intent_json": {
      "type": "string",
      "description": "The exact JSON output generated by the refine-intent skill."
    }
  },
  "required": ["refined_intent_json"]
}
```

## Execution Instructions (For the LLM Agent)

When this tool is invoked, you MUST strictly adhere to the following rules:

1. **No Technical Implementation:** You MUST NOT define databases, APIs, code architecture, or specific file changes. Focus exclusively on *what* the system does from a user or state perspective, not *how* it does it technically.
2. **Divergence Guardrail:** You MUST NOT invent new business rules. You are constrained entirely by the `refined_intent_json` payload. If the intent is incomplete, output a warning.

### The Output Format

You MUST generate the output as a Markdown document structured exactly like the "Business View" template defined in our SDD guidelines.

```markdown
### 1. Intent Summary
[2-3 clear, jargon-free sentences explaining what this feature achieves for the user or business.]

### 2. State Machine / User Flow
[Insert a Mermaid.js diagram (e.g., `graph TD` or `stateDiagram-v2`) visually mapping the flow. Ensure the diagram is readable and logically sound.]

### 3. Strict Business Rules
* [Rule 1: Extracted from Refined Intent]
* [Rule 2: e.g., "User cannot proceed if balance is zero"]

### 4. Non-Functional Requirements (NFRs)
* [e.g., "Must support 1000 concurrent users", "Must be WCAG AA compliant"]

### 5. Out of Scope
* [Explicitly list what is NOT happening in this flow.]
```

### Action After Generation

Once generated, you MUST present this output to the user. This forms the baseline context for the subsequent `generate-qa-view` step.
