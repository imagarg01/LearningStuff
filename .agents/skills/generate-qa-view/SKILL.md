# generate-qa-view

This skill acts as the second step in the "Translation Layer" (Stage 2) of Spec-Driven Development (SDD). It creates the "Executable Specification" by translating business rules into strict Gherkin format (BDD) drawing from Dan North's philosophy.

## Usage

Use this skill immediately after the `generate-ba-view` skill has completed.

### Parameters (JSON Schema)

```json
{
  "type": "object",
  "properties": {
    "refined_intent_json": {
      "type": "string",
      "description": "The exact JSON output generated by the refine-intent skill."
    },
    "ba_view_markdown": {
      "type": "string",
      "description": "The markdown output generated by the generate-ba-view skill."
    }
  },
  "required": ["refined_intent_json", "ba_view_markdown"]
}
```

## Execution Instructions (For the LLM Agent)

When this tool is invoked, you MUST strictly adhere to the following rules:

1. **Strict Dependency Chain:** You MUST NOT invent new logic. You are strictly bounded by the state machine and rules defined in the `ba_view_markdown`. Your job is to extrapolate boundary tests (edge cases) that *prove* the BA's logic is sound.
2. **The Anti-Complacency Gate:** You must actively hunt for logical holes. What happens on network timeouts? What happens if the user double-clicks? What if the input is null?
3. **Executable Format:** You MUST format your output in strict Gherkin (`Feature`, `Scenario`, `Given`, `When`, `Then`). This output is intended to be executed by tools like Cucumber, Playwright, or Cypress.

### The Output Format

You MUST generate the output exactly as follows:

```markdown
### Edge Case Extrapolation (Anti-Complacency Gate)
* [List 2-3 specific edge cases or boundary conditions that the AI has actively identified which might break the BA's happy-path flow].

### BDD Executable Spec (Gherkin)

```gherkin
Feature: [Feature Name]
  As a [Role]
  I want [Capability]
  So that [Benefit]

  Scenario: [Happy Path Scenario]
    Given [Initial State]
    When [Action]
    Then [Expected Result]

  Scenario: [Edge Case Scenario 1]
    Given [Boundary State]
    When [Action]
    Then [Expected Error/Result]
```
*(Continue generating scenarios until all business rules and edge cases are exhausted)*
```

### Action After Generation

Once generated, you MUST present this output to the user. This forms the baseline context for the final `generate-dev-view` step.
